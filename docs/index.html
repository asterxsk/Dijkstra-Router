main.c, line by line

A single C file that builds a 13 × 4 map of 52 locations and finds the shortest route between two of them twice over — once with plain Dijkstra, once with a bidirectional search from both ends.

C, 376 lines, standard headers only (stdio.h and string.h; windows.h on Windows just for the console). Build with gcc -Wall -Wextra main.c -o main and run ./main (Windows: main.exe).

The first map appears before any search. The second is drawn after the route is found; in a colour terminal the legend and the route are also tinted. With the colour escapes stripped, the two maps are character for character identical — the second simply gains the legend line printed under its heading.

The grid model

Thirteen rows named A to M, four columns numbered 1 to 4. Each location gets its number and its name from the same two loops, which is why the diagram below matches the printed map.

number = row * 4 + column (both counting from 0) name = 'A' + row, then column + 1

So A1 is 0, A2 is 1, A3 is 2, A4 is 3, B1 is 4, and so on to M4 at 51. Every place is joined to the one on its right and the one below, and each road is written into the matrix both ways, so travel works in both directions.

The distances are not hand-written; each road’s weight comes from a formula, which keeps the map varied in four lines instead of a long list that is easy to mistype. The % 7 is the remainder after dividing by seven, giving 0–6, and adding 3 lifts the result to 3–9:

road to the right : 3 + ((row * 2 + column * 3) % 7) road downward : 3 + ((row * 3 + column * 5) % 7)

Because the two formulas use different multipliers, horizontal and vertical roads differ, and the cheapest route tends to zig-zag instead of running straight. The diagram above draws every road with no weight labels — 87 of them across a small picture would be unreadable. The counts are 39 roads across (3 per row × 13 rows) and 48 down (12 per column × 4 columns), 87 in total.

buildNames

Give every location its printed name, A1 through M4, by walking the grid row by row.

32/* name each location: row * 4 + column */ 33void buildNames(void) { 34 int r, c, i = 0; 35 for (r = 0; r < ROWS; r++) { 36 for (c = 0; c < COLS; c++) { 37 sprintf(NAME[i], "%c%d", 'A' + r, c + 1); 38 i++; 39 } 40 } 41} 42
  • 32The comment states the naming rule: a place’s name is decided by row * 4 + column.
  • 33The function takes nothing and returns nothing; it writes into the global NAME array.
  • 34r is the current row, c the current column, and i is the running index 0 to 51. i starts at 0 and only ever grows.
  • 35Outer loop: visit rows 0 to 12.
  • 36Inner loop: visit columns 0 to 3 inside each row.
  • 37Format the name straight into the table. 'A' + r relies on letters being consecutive in ASCII: 'A'+0 is A, 'A'+12 is M. %c prints that letter and %d prints c + 1, so the first column becomes 1. Row 0, column 0 gives "A1"; row 12, column 3 gives "M4".
  • 38Advance i to the next slot. Because the loops run row-major, the slot order is exactly i = r * 4 + c — the same rule the graph uses.
  • 39–40Close the inner and outer loops.
  • 41End of buildNames. After this call, NAME[0] is "A1" and NAME[51] is "M4".

buildGraph

Join every location to its right and below neighbour, storing a formula-generated distance on both ends of each road.

43/* join each location to its right and below neighbour */ 44void buildGraph(void) { 45 int r, c, u, v; 46 47 for (r = 0; r < ROWS; r++) { 48 for (c = 0; c < COLS; c++) { 49 u = r * COLS + c; 50 if (c + 1 < COLS) { 51 v = r * COLS + (c + 1); 52 graph[u][v] = graph[v][u] = 3 + ((r * 2 + c * 3) % 7); 53 } 54 if (r + 1 < ROWS) { 55 v = (r + 1) * COLS + c; 56 graph[u][v] = graph[v][u] = 3 + ((r * 3 + c * 5) % 7); 57 } 58 } 59 } 60} 61
  • 43Comment: each place is joined only to the neighbour on its right and the one below it.
  • 44Function signature; it fills the global graph.
  • 45u is the current location, v its neighbour.
  • 47Outer loop over rows.
  • 48Inner loop over columns.
  • 49Convert (row, column) to the single location number 0 to 51, the same rule used for names.
  • 50Is there a column to the right? Column 3 has none, so the right road is skipped on the last column.
  • 51The index of the right neighbour: same row, next column.
  • 52Set the road in both directions at once (graph[u][v] = graph[v][u] = …), which is what makes the graph undirected. The distance comes from the “right road” formula: (r*2 + c*3) % 7 gives 0 to 6, and adding 3 gives 3 to 9. Both row and column feed the formula, so different places get different weights — this is why the map is not uniformly weighted, and why a straight line is often not the cheapest route.
  • 53Close the right-neighbour check.
  • 54Is there a row below? The last row has none, so the down road is skipped there.
  • 55The index of the neighbour below: next row, same column.
  • 56The same two-way assignment, using the “down road” formula (r*3 + c*5) % 7, again scaled to 3 to 9. It uses different multipliers (3 and 5 instead of 2 and 3) so horizontal and vertical roads follow different patterns.
  • 57Close the down-neighbour check.
  • 58–59Close the inner and outer loops.
  • 60End of buildGraph. Every road is written twice, so the matrix is symmetric and the graph is undirected.

findNode

Turn a typed name such as b2 or B2 into a location number 0 to 51, or -1 when the name is not a real location.

132/* "b2" or "B2" -> location number, or -1 */ 133int findNode(const char *name) { 134 char wanted[4]; 135 int i; 136 137 for (i = 0; name[i] != '\0' && i < 3; i++) { 138 wanted[i] = name[i]; 139 if (wanted[i] >= 'a' && wanted[i] <= 'z') wanted[i] -= 32; 140 } 141 wanted[i] = '\0'; 142 143 for (i = 0; i < N; i++) { 144 if (strcmp(NAME[i], wanted) == 0) return i; 145 } 146 return -1; 147}

dijkstra

Find the cheapest route from start to goal, recording each place’s predecessor so the route can be rebuilt afterwards.

159/* O(N^2): settle the cheapest unfinished location each round, relax its neighbours */ 160int dijkstra(int start, int goal, int prev[], int *settledCount) { 161 int dist[N], settled[N]; 162 int i, step; 163 164 for (i = 0; i < N; i++) { 165 dist[i] = INF; 166 settled[i] = 0; 167 prev[i] = -1; 168 } 169 dist[start] = 0; 170 *settledCount = 0; 171 172 for (step = 0; step < N; step++) { 173 int u = -1; 174 for (i = 0; i < N; i++) { 175 if (settled[i] == 0 && dist[i] < INF) { 176 if (u == -1 || dist[i] < dist[u]) u = i; 177 } 178 } 179 if (u == -1) break; 180 181 settled[u] = 1; 182 (*settledCount)++; 183 184 if (u == goal) break; 185 186 for (i = 0; i < N; i++) { 187 if (graph[u][i] != 0 && dist[u] + graph[u][i] < dist[i]) { 188 dist[i] = dist[u] + graph[u][i]; 189 prev[i] = u; 190 } 191 } 192 } 193 return dist[goal]; 194}
  • 159Comment naming the cost: the function is O(N²) because each round scans all places for the cheapest unfinished one.
  • 160Signature. prev[] and settledCount are outputs: the caller receives the predecessor chain and the number of places settled.
  • 161dist[i] is the best distance found so far from the start to place i; settled[i] becomes 1 once that distance is final and can never improve.
  • 162Loop counters: i for scans, step for the outer rounds.
  • 164–168Initialise everything: every distance is INF (unknown), nothing is settled, and no place has a predecessor yet. This is the “we know nothing except the start” state.
  • 169The start is zero away from itself.
  • 170Zero the caller’s settled counter before counting.
  • 172The main loop, running at most once per place.
  • 173u will hold the cheapest unsettled place. Starting it at -1 means “none found yet”.
  • 174Scan every place to find that cheapest one.
  • 175Only consider places that are both unsettled and actually reachable. The dist[i] < INF guard is what skips places the search has not reached; this double condition is the O(N²) minimum scan named in the comment.
  • 176If this place is better than the best so far, remember it. The u == -1 test handles the first candidate.

bidirectionalDijkstra

Search outward from the start and the goal at the same time, remember the cheapest place where the two searches meet, and rebuild the route through it.

Data structures

NAME[52][4] holds the 52 names in 4-byte slots — up to three characters plus a terminator, so 208 bytes in all — filled once by buildNames.

graph[52][52] is the adjacency matrix. Entry graph[u][v] is the distance between u and v, or 0 for “no road”. It holds 2704 integers; on a machine with 4-byte int that is 10,816 bytes, about 10.8 KB. There are 87 roads and each is stored twice (once as graph[u][v], once as graph[v][u]) for symmetry, so just 174 of the 2704 entries are non-zero — the matrix is 93.6% empty.

For 52 locations a matrix beats an edge list on every usability axis: neighbour lookups are a single indexed read, the code stays short, and 10.8 KB is nothing here. An adjacency list would use far less memory and suit a much larger, sparser map — but at this size it would only add bookkeeping, and every algorithm in the file reads the graph the same simple way.

Cost

Plain dijkstra runs in O(N²) time, because every round scans all N places for the cheapest unsettled one — about 2700 steps at N = 52. It needs O(N) extra space for dist, settled and prev, on top of the O(N²) graph itself. A heap would lower the time to O((N + E) log N).

bidirectionalDijkstra runs two searches with the same per-side cost, so it is also O(N²) here, but it often settles fewer places in total because the searches meet in the middle. On this long, thin map the saving is real but modest, and it shrinks as the two ends get further apart.

“Places settled” is how many locations each search finished for good — how far it had to sweep before the answer was proven. Two verified runs:

RoutePlain settledBidirectional settledCost
A1 → M45226 forward + 25 backward = 5177
G3 → K23414 forward + 12 backward = 2628

On opposite corners (A1 to M4) the two searches together settle 51 of 52 places — barely better than the one-sided search, because each still sweeps most of the map’s length. On G3 to K2 they settle 26, about a quarter less. The worst case gives almost no saving, which is the honest result rather than the “twice as fast” figure often quoted.
